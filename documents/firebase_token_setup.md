# Firebase Token Setup Guide

## Overview

`GET /teiserver/api/firebase_token` mints a
[Firebase custom token](https://firebase.google.com/docs/auth/admin/create-custom-tokens)
for the calling user, so a client already authenticated against Teiserver can
sign in to Firebase as the same identity.

The token is an RS256 JWT signed with a Google service account key, generated by
`Teiserver.Firebase.CustomToken` using [Joken](https://hexdocs.pm/joken/).

> A custom token is a full Firebase sign in. Firebase exchanges it for a session
> the client can refresh indefinitely, and revoking the Teiserver credential that
> produced it does **not** revoke the Firebase session. The endpoint therefore
> refuses to mint tokens for accounts restricted from logging in or flagged as a
> smurf.

## Configuration

Firebase auth is optional. With nothing configured the endpoint returns a 500
explaining which value is missing, and everything else in Teiserver runs
normally.

### Credentials

The values come from your service account JSON:

| Env var | Source | Notes |
| --- | --- | --- |
| `TEI_FIREBASE_EMAIL` | `client_email` | |
| `TEI_FIREBASE_PRIVATE_KEY_FILE` | path to a file holding `private_key` | Preferred. Defaults to `/run/secrets/firebase_private_key` |
| `TEI_FIREBASE_PRIVATE_KEY` | `private_key` | Fallback, used only when the file above is absent |

The key must be the full PEM including the `-----BEGIN PRIVATE KEY-----` and
`-----END PRIVATE KEY-----` lines.

Prefer the file form. PEM keys are multi-line, and most `.env` parsers and
process managers mangle multi-line values. If you must use
`TEI_FIREBASE_PRIVATE_KEY`, put the whole key on one line with literal `\n`
sequences — `Teiserver.Firebase.CustomToken` unescapes those and strips
surrounding quotes:

```bash
TEI_FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBg...\n-----END PRIVATE KEY-----\n"
```

Both are read in `config/runtime.exs`, never at compile time — a service account
key must not end up baked into a compiled release.

**Never commit these credentials.** `/secrets/` is gitignored.

### Local development with compose

`compose.yaml` passes `TEI_FIREBASE_EMAIL` through from your shell and points
`TEI_FIREBASE_PRIVATE_KEY_FILE` at `./secrets/firebase_private_key.txt` inside the
mounted workspace. To enable the endpoint locally:

```bash
mkdir -p secrets
cp /path/to/service-account-private-key.pem secrets/firebase_private_key.txt
export TEI_FIREBASE_EMAIL=your-service-account@your-project.iam.gserviceaccount.com
docker compose up
```

Skip those steps and compose still starts; the endpoint just reports that
Firebase isn't configured.

### Production

Mount the key as a secret at `/run/secrets/firebase_private_key` (the default),
or point `TEI_FIREBASE_PRIVATE_KEY_FILE` at wherever your orchestrator puts it.

## Authentication

The endpoint accepts an `Authorization: Bearer <token>` header holding any of:

1. a **Guardian access token** — the web session credential
2. an **OAuth access token** — must carry the `firebase` scope
3. an **account user token** — a personal API token

Guardian and account user tokens are the user acting as themselves, so they are
not scope checked. OAuth tokens are delegated to a third party application, so
the application must be registered with the `firebase` scope and the user must
grant it — otherwise the request is rejected. Refresh tokens, expired tokens and
bot-owned OAuth tokens are all rejected.

### Request

```bash
curl http://localhost:4000/teiserver/api/firebase_token \
  -H "Authorization: Bearer YOUR_TEISERVER_ACCESS_TOKEN" \
  -H "Accept: application/json"
```

### Responses

`200` — success. `uid` is the Teiserver user id as a string.

```json
{
  "token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "uid": "12345"
}
```

`401` — no or unusable credentials:

```json
{ "error": "unauthenticated" }
```

```json
{ "error": "invalid_token" }
```

`403` — the credential is valid but the account may not log in:

```json
{ "error": "account_restricted" }
```

`500` — Firebase is not configured, or the configured key could not sign:

```json
{ "error": "firebase email is not configured" }
```

```json
{ "error": "Failed to generate token" }
```

## Token contents

Valid for one hour from issue:

| Claim | Value |
| --- | --- |
| `iss` | the service account email |
| `sub` | the service account email |
| `aud` | `https://identitytoolkit.googleapis.com/google.identity.identitytoolkit.v1.IdentityToolkit` |
| `iat` | issue time |
| `exp` | `iat + 3600` |
| `uid` | the Teiserver user id, as a string |

Clients should re-request rather than cache past expiry.

## Note for existing API clients

`Teiserver.Account.ErrorHandler` now answers unauthenticated JSON requests with
a `401` and a JSON body instead of a `302` redirect to `/login`. This applies to
every endpoint in the `:token_api` pipeline, not just this one. Clients that
followed the redirect need updating.

## Troubleshooting

**`firebase email is not configured` / `firebase private key is not configured`**
The env vars aren't reaching the app. Both are read in `config/runtime.exs`;
check them inside the running container, not just on the host.

**`Failed to generate token`**
The key was found but couldn't be used to sign — the PEM is malformed, usually
from lost newlines. The server log records the failure; the key itself is
deliberately never logged.

**Firebase rejects the token**
Confirm the `aud` matches your project's Identity Toolkit audience, that `iss`
matches the service account email, and that the signing key is the one
registered with that service account.
